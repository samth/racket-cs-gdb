### Return compression

functions called from Scheme (S_mutex_release 6843, S_mutex_acquire 6809, copy_normalize 2844, ...).

### Call/return reconstruction
With noretcomp + TSC jitdump, fib(20) decodes completely: 21891 entries to fib+0x0 (= calls of fib for n=20).
But no Chez call or return is a call/ret instruction:
- call: `lea 0x20(%rip),%rcx; mov %rcx,0(%r13); jmp *0xd(%r12)`  (perf flag "jmp")
- return: `jmp *0x0(%r13)` (perf flag "jmp")
The chain build reserves %rbp for the chain but uses the same jmp sequence.
So `perf script --call-trace` shows only C calls (fib appears 8 times, flat) and any call/ret-based
reconstruction (magic-trace included) will see Chez calls as jumps: tail-call-like replacement of frames,
or no depth growth, rather than a nested stack. Reconstructing Chez stacks from PT needs a decoder that
treats "store return address to 0(%sfp) + indirect jmp" as a call and "jmp *0(%sfp)" as a return
(or uses the frame-size/return-point info the sampler already uses).

## Chez-aware PT stack reconstruction (2026-11-01)
Building magic-trace from source was blocked: the opam install of its dependencies was denied by
the session's permission classifier ("Code from External"). So this is a standalone reconstructor:
/tmp/mtrace/ptstack/chez_pt_stacks.py (+ chez-pt.sh wrapper: record, inject, script, reconstruct).

Rules (code bytes come from the jitdump's JIT_CODE_LOAD records):
- non-tail call: jmp preceded within 40 bytes by `lea ret(%rip),%reg` then `mov %reg,0x0(%r13)`: push (callee, ret, mvret)
  where mvret is the 8-byte word at ret-0x20 in the return-point header.
- return: any jmp whose target is a pending frame's ret or mvret pops to that frame. This covers `jmp *0x0(%r13)`,
  `jmp *%r12` (single-value return through a register) and `jmp *-0x20(%r12)` (multiple-value return).
  A `jmp *0x0(%r13)` with no matching frame resyncs: pop one frame and rename the top.
- tail call: other jmp to a code-object entry (+0x0): rename the top frame.
- C: real call pushes (ret = ip+ilen); real ret pops to the matching frame, else renames the top.
First version without mvret leaked frames (depth 177): `rd-token` returns 2 values via `jmp *-0x20(%r12)` to ret+10.

fib(20), TSC jitdump + noretcomp (pt/fib3.*):
- fib entries 21891 (exact), max fib nesting 20 (from the Chrome trace), e.g.
  <root>;_start;...;main;Sscheme_start;boot_call;S_call_help;invoke;dynamic-wind;[anonymous];dynamic-wind;dynamic-wind;ksrc;compile;map;fib;fib;...
  (same shape as the in-process sampler's stacks)
- Scheme-event depth before (magic-trace): depth 1 for 97%. After: 0-1 0.0%, 2-5 0.0%, 6-10 0.2%, 11-20 6.9%, 21-40 89.8%, 41-80 3.1%; max 80
  (the deep ones are genuine non-tail self-recursion in compiler helpers, e.g. a list walk named `float`).
- classified: 38926 non-tail calls, 9303 tail calls, 37504 returns via jmp *0(%r13) matched, 1409 other-jmp returns matched
  (mv and jmp *%r12), 5 unmatched frame returns (resync).
- 23595 C rets unmatched, all into [unknown] code: Scheme code without jitdump records (boot code before S_jitdump_boot_done),
  where perf cannot decode, so the matching calls never appear. Top: S_mutex_acquire 7668, S_mutex_release 7663, copy_normalize 3177.
